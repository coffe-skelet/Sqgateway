How The Gateway Saves Tokens

Three independent mechanisms. All numbers from live measurements on gemini-3.6-flash (October 2026); methodology reproducible with commands from "Verification" section.

Request Pipeline

// Step 1 calculate

Baseline Measurement

Gateway receives request in Gemini API format and asks provider how many tokens the original prompt would cost via countTokens. This is the reference point for all savings — without it, any "we saved" claims would be marketing.

// Step 2 compress

Input Compression

C++ core removes politeness and bureaucratic phrases, deduplicates repeating lines. On dense technical prompts — barely touches anything: "don't harm" priority exceeds savings.

// Step 3 psychology

Thinking Depth

Classifier by complexity markers decides if thinking level can be lowered. "What is / translate / briefly" → LOW, "explain / prove / solve" → MEDIUM. Explicit client choice always respected.

// Step 4 send

Send & Account

Request goes to provider with retries on 503 and clear error on 429. Each request written to JSONL: input, thinking, output, latency, and gateway auxiliary cost.

Frequently Asked Questions

How much exactly does the gateway save?
Depends on traffic. On simple chat questions total −40…60% (mainly from thinking control), on medium "explain/why" — 30–40%, on dense technical tasks — 15–30% (compression barely helps there, and we don't lower thinking). On mixed traffic of real application — target 30% achieved with margin.
Does compression harm answer quality?
This is the main risk, limited three ways: (1) heuristic only touches politeness/bureaucracy/repeats, not data; (2) on dense prompts it stops itself (−6% or 0%); (3) LLM-compression activates only from 2000 chars and falls back to heuristic on empty result. On tests clean prompt stays untouched — separate check in logs.
Why can model "think" less — won't that degrade answers?
For simple tasks — no: measurement showed that on defining quantum entanglement LOW gave same quality answer in 6 seconds instead of 17 and 493 tokens instead of 918. For complex tasks (proofs, multi-step reasoning) classifier leaves MEDIUM — lowering there is harmful, and we don't do it.
Which models are supported?
Today — Gemini 3.x (3.5 / 3.6; 3.8 works but sometimes overloaded on Google side). Architecturally gateway designed as universal: OpenAI and Claude have similar controls (reasoning_effort / thinking), and input planned in OpenAI-compatible format — then any client can switch base URL and get same optimizations.
What happens with my API key and data?
Key stored only in .env on your machine and never committed to repository (.env in .gitignore). Requests go directly to Google, bypassing third-party servers; metrics log — local file logs/metrics.jsonl without prompt text: only tokens, latency, and mode.
Can I verify the measurements myself?
Yes. Repository has tests/ (thinking levels), CLI client, and metrics log. Any number from this page is reproducible: launch gateway, ask question in passthrough and optimized mode, compare usageMetadata. Methodology honest: baseline taken from provider via countTokens, not estimated "by eye".
