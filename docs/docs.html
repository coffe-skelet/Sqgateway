Как шлюз экономит токены

Три независимых механизма. Все цифры — из живых замеров на gemini-3.6-flash (октябрь 2026); методика воспроизводится командами из раздела «Проверка».

Пайплайн запроса

Что происходит между вашим приложением и моделью

1 · Приём и замер baseline

countTokens

Шлюз принимает запрос в формате Gemini API и спрашивает у провайдера, сколько токенов потребовал бы оригинальный промпт. Это опорная точка всей экономии — без неё любые «мы сэкономили» были бы маркетингом.

2 · Сжатие ввода

−5…36%

C++ ядро снимает вежливость и канцелярит, дедуплицирует повторяющиеся строки. На плотных технических промптах — почти ничего не трогает: приоритет «не навредить» выше экономии.

3 · Глубина мышления

−46% на простых

Классификатор по маркерам сложности решает, можно ли понизить thinking-уровень. «Что такое / переведи / кратко» → LOW, «объясни / докажи / реши» → MEDIUM. Явный выбор клиента всегда уважается.

4 · Отправка и учёт

baseline − факт − aux

Запрос уходит провайдеру с ретраями на 503 и понятной ошибкой на 429. Каждый запрос пишется в JSONL: ввод, мысли, ответ, латентность и служебный расход шлюза.

LLM-сжатие

порог 2000 симв.

Мини-модель переписывает длинный промпт, сохраняя факты и требования. На коротких промптах убыточно: компрессор сам стоит ~300 aux-токенов. Поэтому — порог окупаемости.

Интеграция

Замените базовый URL — остальной код не меняется

# эвристика + авто-глубина мышления
curl -X POST "http://localhost:8082/v1beta/models/gemini-3.6-flash:generateContent?squeeze=1&thinking=auto" \
  -H "Content-Type: application/json" \
  -d '{"contents":[{"role":"user","parts":[{"text":"Что такое FFT? Кратко."}]}]}'
import httpx

url = ("http://localhost:8082/v1beta/models/"
       "gemini-3.6-flash:generateContent?squeeze=1&thinking=auto")
r = httpx.post(url, json={"contents": [{
    "role": "user",
    "parts": [{"text": "Что такое FFT? Кратко."}],
}]}, timeout=120)
print(r.json()["candidates"][0]["content"]["parts"][0]["text"])
const res = await fetch(
  "http://localhost:8082/v1beta/models/gemini-3.6-flash:generateContent?squeeze=1&thinking=auto",
  {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ contents: [{
      role: "user", parts: [{ text: "Что такое FFT? Кратко." }],
    }] }),
  });
const data = await res.json();

Ответы на вопросы

Коротко и без маркетинга

Сколько именно экономит шлюз?
Зависит от трафика. На простых чат-вопросах суммарно −40…60% (в основном за счёт контроля глубины мышления), на средних «объясни/почему» — 30–40%, на плотных технических задачах — 15–30% (сжатие там почти нечего даёт, а мышление мы не понижаем). На смешанном трафике реального приложения — целевые 30% достигаются с запасом. На дашборде процент ниже: он считает только вход и служебные траты на текущей выборке, без контрфактического замера thinking — эти цифры берутся из парных тестов.
Не портит ли сжатие качество ответов?
Это главный риск, и он ограничен тремя способами: (1) эвристика трогает только вежливость/канцелярит/повторы, но не данные; (2) на плотных промптах она сама себя останавливает (−6% или 0%); (3) LLM-сжатие включается только от 2000 символов и откатывается на эвристику при пустом результате. На тестах чистый промпт остаётся нетронутым — это отдельная проверка в журнале.
Почему модель может «думать» меньше — это же ухудшает ответы?
Для простых задач — нет: замер показал, что на определении квантовой запутанности LOW дал ответ того же качества за 6 секунд вместо 17 и 493 токена вместо 918. Для сложных задач (доказательства, многошаговые рассуждения) классификатор оставляет MEDIUM — понижение там вредно, и мы этого не делаем.
Какие модели поддерживаются?
Сегодня — Gemini 3.x (3.5 / 3.6; 3.8 работает, но бывает перегружена на стороне Google). Архитектурно шлюз проектируется как универсальный: у OpenAI и Claude аналогичные рычаги (reasoning_effort / thinking), а вход планируется в OpenAI-совместимом формате — тогда любой клиент сможет переключить base URL и получить те же оптимизации.
Что происходит с моим ключом и данными?
Ключ хранится только в .env на вашей машине и никогда не коммитится в репозиторий (.env в .gitignore). Запросы идут напрямую в Google, минуя сторонние серверы; журнал метрик — локальный файл logs/metrics.jsonl без текста промптов: только токены, латентность и режим.
Почему в бесплатном режиме иногда ошибка 429?
Это дневная квота Google на бесплатном тарифе (≈20 генераций в день на модель), а не ошибка шлюза. Ретраи при 503 тоже расходуют квоту — поэтому шлюз ретраит только перегрузку, а на 429 сразу отдаёт понятное сообщение. Для полноценных замеров нужен тариф с оплатой.
Можно ли проверить замеры самому?
Да. В репозитории есть tests/ (уровни мышления), CLI-клиент и журнал метрик. Любая цифра из этой страницы воспроизводится: запустите шлюз, задайте вопрос в passthrough и в оптимизированном режиме, сравните usageMetadata. Методика честная: baseline берётся у провайдера через countTokens, а не оценивается «на глаз».
Это законно и не нарушает условия провайдеров?
Да: шлюз использует официальный API с вашим ключом и не автоматизирует веб-интерфейсы. Официальные платформенные входы (Vertex AI / Azure OpenAI / Bedrock) — легальный путь для корпоративных аккаунтов, который мы планируем поддержать. Вход через личные веб-аккаунты ChatGPT/Claude — вне рамок проекта, так как нарушает ToS.
